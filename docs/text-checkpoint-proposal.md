# Proposal: first text checkpoint (for review)

Status: the pipeline for these defaults is implemented (2026-10-13; see "Pipeline" below). Tokenizer parity (criterion 1) is met. Both permitted runs failed the probe gate on name copying (see "First run findings" and "Retry findings"). The gate is not met. The 48,000-step checkpoint is subsequently shipped at the project owner’s request as an experimental real-text model; this does not turn the failed gate into a pass. See `tinystories-deployment.md`. A revised name-copying probe is drafted in `docs/text-checkpoint-probes-v2.md`.

## Goal

A small checkpoint trained on TinyStories V2 that runs interactively in the browser. It must have a fully specified tokenizer that the browser reproduces exactly, and a set of probes with known correct answers, so that interventions on real text show measured, checkable effects. Like the retrieval model, it is a teaching instrument, not a general language model.

## Data

- **Source:** TinyStories V2 (GPT-4) at the pinned revision in `docs/tinystories-source.json` (CDLA-Sharing-1.0 on the dataset card; the generator's terms also need review before weights are redistributed).
- **Preprocessing:** split stories on `<|endoftext|>` and drop the leading fragment in the validation file. Normalize line endings to `\n` and strip surrounding whitespace. No lowercasing or other normalization; anything else is reported, not altered.
- **Training subset:** the first 250,000 stories in file order (about 55M tokens), with a SHA-256 of the subset recorded. The validation file is used only for model selection.
- **Held-out audit:** a separate audit set of 2,000 stories, taken from the end of the training file and excluded from training, kept untouched until the final report. This fixes the retrieval model's weakness, where test data also served as a development gate.

## Tokenizer

- **Type:** byte-level BPE trained by our own Python script on the training subset. Vocabulary 2,048: 256 byte tokens, 1,789 merges, and the specials `<BOS>`, `<EOS>`, `<PAD>`.
- **Pre-splitting:** a documented regular expression, ASCII-oriented, with byte fallback for anything else: `` ?[A-Za-z]+| ?[0-9]| ?[^A-Za-z0-9 \t\n\r]+|[ \t\n\r]+``. Whitespace is listed explicitly because Python's and JavaScript's `\s` differ. Training breaks count ties by the smallest pair; encoding applies the lowest-rank merge first, to every occurrence, left to right. Trained on the first 20,000 training stories.
- **Artifact:** `tokenizer.json` (format version 2) records the regular expression, the ordered merges, the specials, and a hash. The model manifest pins that hash, as it does today.
- **Browser parity:** a TypeScript encoder and decoder must produce byte-identical token IDs to the Python reference on every validation story, and decoding must reproduce the input bytes exactly.
- **Screen changes:** free-text input replaces the symbol list for this checkpoint. Tokens are displayed as decoded pieces, with spaces made visible.

## Model

| Setting | Value |
| --- | --- |
| Architecture | Unchanged contract (`preln-absolute-tied-v1`) |
| Layers / heads / d / MLP | 4 / 4 / 128 / 512 |
| Vocabulary / context | 2,048 / 64 tokens |
| Parameters / weights | 1.06M / 4.1 MiB float32 |

A 64-token context keeps the attention matrix (64 × 64 cells) usable on phones. Longer contexts first need a virtualized attention view.

Measured on this container (4 CPU cores, PyTorch 2.9.1 reference model, batch 32 × 64, Adam): an early benchmark gave about 430 ms per step; the implemented trainer runs at about 80 ms per step (about 26,000 tokens/s). A 2.59M-parameter, 128-context alternative ran at about 1,800 tokens/s.

## Training budget

- 24,000 steps of 32 × 64 tokens, roughly 50M tokens or about one pass over the training subset. At the measured speed that is about 35 minutes on this container's 4 cores; other hosts differ.
- The training recipe follows the retrieval trainer: Adam, gradient clipping 1.0, cosine decay, and checkpoint selection by validation loss every 500 steps. One recorded seed.
- A second identical run must reproduce the same weight hash on this host, as was done for the retrieval model.

## Acceptance criteria

All criteria are fixed before training.

1. **Tokenizer parity:** Python and TypeScript token IDs are identical on 100% of validation stories, and decoding round-trips exactly.
2. **Language-model quality:** validation loss (nats per token) clearly beats a train-estimated bigram model, by at least 1.0 nat/token, and also beats unigram. The audit-set loss is reported once, at the end.
3. **Probes:** synthetic, generated by our own code, with held-out name and object lists. Each is reported with counts and the prompt template.
   - **Name copying (induction):** "… a girl named Lily … Lily" must be the top-1 prediction at the second mention in at least 80% of 200 prompts. A control where the name never appeared must show it near the base rate.
   - **Pronoun agreement:** p("he") > p("she") after a named boy, and the reverse for a girl, in at least 80% of 200 prompts.
   - A probe that falls short is reported as a finding; thresholds are not lowered.
4. **Numerical parity:** independent PyTorch forward, gradient, Adam, and intervention fixtures for this checkpoint pass in Node and in browser CPU and WebGL, with the existing tolerances unchanged.
5. **Interactivity:** warm end-to-end comparison latency under 200 ms on the named desktop host, measured with the existing benchmark. Cold load is reported.
6. **Limits documented:** template-generated text, short context, GPT-4-generated training data, no general-language claims, and no semantic labels for heads.

## Pipeline

All outputs go to `.cache/` (not committed). Run from the repository root after `uv sync --locked`:

```sh
.venv/bin/python scripts/text_data.py            # fetch the pinned files, verify sizes and SHA-256, write the subsets and prepared.json
.venv/bin/python scripts/text_tokenizer.py       # train the BPE tokenizer; prints its SHA-256
.venv/bin/python scripts/train_text.py           # train, select by validation loss, export; --resume continues from the checkpoint
.venv/bin/python scripts/text_probes.py          # run the gating probes against the export
```

- `text_tokenizer.py` on the default subsets must print SHA-256 `bea77691157fbd7c2e339aa80e421057392fdda28dd003625336ed70dd0fc551`, the tokenizer whose parity was checked.
- `train_text.py` writes `.cache/text/export/` (manifest, tokenizer, weights, `training.json`). `training.json` records the environment, unigram and bigram baselines, criterion 2's result, and the validation history. Validation loss is the mean of two window sets: story openings and seeded random offsets.
- Determinism: two runs, and a run stopped at step 100 and resumed, produced the same weight hash on this container (300-step smoke runs). Different hosts or PyTorch builds may not match each other; record the hash from the host that trains.
- `text_probes.py` writes `probes.json` next to the model. The name and object lists are fixed in the script; the names are common in TinyStories (they must be single tokens), so they are not held out from training.
- Tests: `npm run test:data` (Python; the standard-library tokenizer tests also run in CI), `npm test` (TypeScript encoder), and `npm run parity:tokenizer` (every validation story; needs `scripts/export_text_tokenizer.py --all` first).

## First run findings

From the first local run (default settings, seed 2026, 24,000 steps; macOS arm64, PyTorch 2.9.1, CPU, 4 threads, 1,881 s). Weights SHA-256 `174f1f72d4558d86be4842afe5cc79b981c08fc238a798d22e764cf55fe43149`; 49.2M tokens seen. The determinism re-run has not been made on this host.

- **Criterion 2:** met. Selected step 23,500. Validation loss (nats/token):

  | Window set | Model | Bigram | Unigram |
  | --- | --- | --- | --- |
  | Openings | 1.463 | 3.117 | 5.728 |
  | Random offsets | 2.212 | 3.704 | 5.902 |
  | Mean | 1.838 | 3.410 | 5.815 |

  End of the validation history (mean): 1.847 at step 21,500, 1.844 at 22,000, 1.842 at 22,500, 1.841 at 23,000, 1.838 at 23,500, 1.838 at 24,000. It was still falling slowly when the cosine schedule ended.
- **Pronoun agreement:** 200 of 200 (threshold 80%). Passed.
- **Name copying, as first implemented:** 37 of 200 top-1 (18.5%). Not passed. That probe was an implementation error: its templates put two names in context (for example "{A} and {B} went to the {place}. {B} gave a {object} to") and required the earlier one, which tests choosing between names, not the single-name repeat the proposal specifies. Diagnostics on the same prompts:
  - The right name beats a name absent from the prompt in 77% of prompts; mean probability 0.134 against 0.009. The model raises the probability of names it has read.
  - The right name beats the other mentioned name in only 41% of prompts (mean 0.134 against 0.118). It does not pick the correct one.
  - Top-1 predictions are mostly function words: " the" 45, " his" 39, " her" 21.
  - Per template: 9%, 6%, and 41%.
- **Name copying, as specified (`nameRepeat`):** 155 of 200 top-1 (77.5%). Not passed. It is just under the 80% threshold, and the threshold stays at 80%. Per template: 55/67, 57/67, 43/66. The name outranks every other listed name in 97% of prompts; mean probability 0.453, against 0.003 for an absent name (the control).
- **Gate:** not met. Criterion 3 fails on name copying, so this run is not an accepted checkpoint.
- **How the two name probes came about:** the two-name result stays recorded as a failure, under its own name (`twoNameChoice` in `probes.json`). The proposal's single-name probe (`nameRepeat`) was added afterwards, with templates written before seeing any result for them, and with the same 80% top-1 threshold over 200 prompts. Its control is the probability of a name absent from the prompt, and it also reports how often the name outranks every other listed name.

## Retry

Decided 2026-10-12, after the first run failed and before the retry was trained: one retry at 48,000 steps (about 98M tokens, nearly two passes over the training subset). Nothing else changes: seed 2026, data, tokenizer, learning-rate schedule shape, the selection rule, probes, prompt seed, templates, and thresholds are as in the first run. The cosine decay stretches over the longer run. The reason is that the first run's validation loss was still falling when the schedule ended.

- This is the only retry. If it also fails, the gate stays failed, and there is no further tuning of steps, schedule, seed, templates, or thresholds to clear 80%.
- Both runs are reported here, whatever the outcome. The first run's export stays in `.cache/text/export/`; the retry writes to `.cache/text/export-48k/`.
- The determinism check (a second identical run with the same weight hash) applies to the retry.

```sh
.venv/bin/python scripts/train_text.py --steps 48000 --output .cache/text/export-48k
.venv/bin/python scripts/text_probes.py --model .cache/text/export-48k
# determinism check (optional second run, compare weightsSha256 in training.json):
.venv/bin/python scripts/train_text.py --steps 48000 --output .cache/text/export-48k-repeat
```

## Retry findings

From the retry (48,000 steps, otherwise as the first run; same host and environment, 3,966 s). Weights SHA-256 `0011a5f8e314f63325a7231dfa60664e5bab37dbd8a27c1e5c03fab45996f294`; 98.3M tokens seen. The determinism re-run has not been made yet.

- **Criterion 2:** met. Selected step 48,000, the last evaluation. Mean validation loss 1.772 nats/token (openings 1.406, random offsets 2.139), against the first run's 1.838 and the unchanged bigram (3.410) and unigram (5.815) baselines. It was still falling slowly at the end: 1.777 at step 44,500, 1.772 at 48,000.
- **Pronoun agreement:** 200 of 200. Passed.
- **Name copying (`nameRepeat`):** 112 of 200 top-1 (56.0%), down from 77.5% in the first run. Not passed. Per template: 64/67, 16/67, 32/66 (first run 55, 57, 43). The name still outranks every other listed name in 91.5% of prompts; mean probability 0.357, against 0.002 for an absent name. The wrong top-1 predictions are pronouns: " her" 32, " she" 28, " his" 16, " he" 6. The second template ends in `"Look!" said`, where " her" (as in "said her mom") is a plausible continuation.
- **`twoNameChoice`:** 48 of 200 (24.0%). Not passed.
- **Gate:** not met. Lower validation loss did not bring higher name-copying accuracy; on two templates it fell. Under the retry rule above, there is no further tuning, and the templates and threshold stay unchanged.
