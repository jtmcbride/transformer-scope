# Computation inspection

## Guided effect trace

**Follow the change** measures the completed baseline and modified head-scaling or attention-redirect runs in one `TRACE` worker command. The engine performs one full forward pass per run, captures all requested stages together, and reuses those captures for residual readouts. It returns norms, maximum component differences, L2 differences, and a per-position architecture route; whole activation tensors remain in the worker. Captures and temporary readout tensors are disposed before responding. Estimated capture storage is bounded at 8 MiB, with at most 8,192 summary rows. Closed tracing adds no trace calls; guided navigation adds no forward passes.

The modified descriptor retains the comparison's selected-position logits. Trace recomputation must reproduce these and the recorded baseline logits within `2e-5 + 1e-5 * abs(recorded)`. A mismatch fails tracing while preserving the completed prediction. Diagnostic readouts use the same final normalization and tied unembedding as the existing lens. The final model-prediction row uses the recorded comparison values. Run IDs, session generation, model revision, backend, and positions identify every report.

`trace-topology.ts` computes possible routes from the head's scaled output for scaling, or from the edited post-softmax attention row for redirects. A redirect changes the output at its query; reading a source does not edit that source's computation. Same-layer scores, normalized inputs, and other heads remain unchanged. Same-position operations retain position; only attention can propagate changes to later positions. The route to the prediction is the downstream/ancestor intersection, independent of measured values or attention magnitude. An exhaustive dependency-graph oracle checks identities, multi-position roots, residual bypasses, final-layer locality, future edits, and one-, two-, and three-layer configurations.

`scripts/export_trace.py` loads hash-checked shipped weights into PyTorch and exports seven cases: the three retrieval recipes and four verification cases (identity, future edit, same-position final-layer scaling, and earlier-position reachability). It produces all per-position stage summaries and prediction-position residual readouts. `tests/fixtures/trace-reference.json` was generated with PyTorch 2.9.1+cpu and NumPy 2.3.3. Regenerate with `npm run fixtures:trace` in the reference environment. Engine and production tests compare every exported stage summary and readout, check snapshot agreement, and verify tensor/cache cleanup after successful, repeated, and failed traces.

The browser tests also check that node and position navigation issue no new `TRACE` or `COMPARE` requests. The persistent toolbar and result summary support keyboard navigation and reduced motion. See `docs/frontend-workspace.md` for user-facing semantics and milestone verification.

Attention redirects use the same captures, with an additional score capture for the edited layer included in the 8 MiB budget. The report returns the edited query's baseline and modified weight rows and score-difference metrics; navigation needs no extra inspection request. `scripts/export_attention_trace.py` exports eight independent cases to `tests/fixtures/attention-trace-reference.json`: a large answer-changing redirect, a tiny effect, a final-layer local edit, an earlier-layer handoff, uniform weights, an edit after the prediction, an uneven row requiring normalization, and an identical-row redirect. The fixture uses the same hash-checked artifact loader and PyTorch 2.9.1+cpu reference. Regenerate with `npm run fixtures:attention-trace`. The topology oracle checks query-row roots on one-, two-, and three-layer configurations independently of source selection. Engine and worker CPU/WebGL tests compare all stage summaries, diagnostic readouts, final snapshots, and overridden rows, including cleanup after repeated measurements.

Attention cells are selectable with a mouse or keyboard. Selecting a cell reads the baseline Q vector at the query position, K vector at the source position, raw score, and masked score row from the computation worker. The panel shows Q·K, head-dimension scaling, the actual computed score, the causal mask, stable-softmax numerator/denominator, and the attention weight. Expand Q/K products for individual dimensions.

The explanatory dot product and softmax use double-precision JavaScript arithmetic on read-back float32 vectors/scores. The worker's score and probability remain separately labeled; small rounding differences are expected. Future-position cells expose the -1e9 mask and zero probability. Same-layer head-output scaling occurs after attention weights are computed, so this map and arithmetic are unchanged by that operation.

The projection/residual/MLP panel is collapsed initially. Expanding it requests only the chosen stage and position for the completed baseline and modified runs. Its selectors can follow the contribution through the edited or a later layer:

1. Attention projection concatenates all head outputs and applies output weights plus the shared bias.
2. Attention residual adds the block input.
3. MLP output is the normalized residual's linear/GELU/linear contribution.
4. Block output adds that MLP contribution to the residual.

The panel defaults to the edited position for a single-position edit, or the prediction position for all-position edits. Each dimension shows baseline, modified, and difference. The table scrolls internally on narrow screens. An observation/reference key prevents a previous slice from appearing under newly selected layer/stage/position labels; obsolete requests cannot overwrite current results.

Exact strength entry validates finite values from 0 to 2, commits on Enter or blur, and leaves the completed experiment intact on invalid input. Slider and numeric entry share the same controls and worker execution path.

“Restart computation worker on CPU” terminates the old worker and creates a fresh session. It preserves valid requested settings against the completed input, and can cancel an unfinished load or probe. Queued computations belong to their original worker; their cleanup cannot unset the new worker's pending state. Existing run IDs, tensors, caches, and probe results are not reused in the new session.

Independent browser fixtures come from `scripts/export_inspection.py`, with seed-weight hashes checked against the installed verification artifact. They include the UI's BOS-prefixed six-token sequence, masked/unmasked cells, and all four stage vectors in both layers at factor .37. Production tests cover numerical parity, numeric validation, baseline reset, mobile containment, restart during edits, and cancellation of a blocked model load.

## Residual-stream read-out

**Read out the residual stream** (collapsed by default) shows the residual vector at the selected prediction position for the baseline and modified runs. It covers the token-plus-position embedding, each layer after attention, and each block output. Every row passes through the final LayerNorm and the tied unembedding, the operations that produce the model's logits (often called a "logit lens"). The panel shows each row's top token, the target's probability, and the residual's L2 norm. Only the last row is the model's prediction. Earlier rows show what that residual would predict if the computation stopped there; the model never computes them, and they are not claims about what a layer "knows."

The worker computes the read-out with one full forward pass, independent of cache state, using `TransformerModel.readOut`. The model's own logits use the same normalization and unembedding code. The panel reads nothing until it is opened.

Verification: `scripts/export_lens.py` loads the shipped retrieval weights into the independent PyTorch model. It checks that they reproduce both recorded logit vectors for the large-effect recipe, then exports read-outs for that recipe's baseline and ablated runs (`tests/fixtures/lens.json`; run `npm run fixtures:exploration`). The engine matches all 120 read-out logits within the forward tolerance (maximum error 1.67e-6), and matches the norms. The final read-out row agrees with the model's logits within the same tolerance but is not bit-identical: a five-row matrix product sums float32 values in a different order than the 16-position forward pass. Invalid positions and released runs are rejected without retaining tensors. A production test compares every displayed top token, probability, and norm with the PyTorch fixture. It checks that the baseline and modified columns agree after reset, and that the panel scrolls within a 390 px viewport.

On that recipe, the baseline read-out first favors `3` after the layer-1 block (78.92%). With Layer 1 Head 4 ablated, the layer-1 block output still favors `3` (71.78%); the answer flips to `0` only after layer-2 attention. This illustrates downstream propagation for one input. It does not show which component "stores" the answer.

Adding this panel exposed a narrow-screen layout fault. On narrow screens the observation column was a `1fr` grid track, so a wide table could widen the whole column beyond the viewport, where the workspace clipped it. The column now has `min-width: 0`, so wide tables scroll inside their panels.

## Input embedding

**Inspect the input embedding** (collapsed by default; position selectable, defaulting to the prediction position) shows where the residual stream starts. It displays the token embedding row, the learned position embedding row, their sum, and the norms. It also shows the cosine between the token and position rows, and the token row's cosine similarity to every other token embedding. Embeddings are weights, so they are identical in the baseline and modified runs. The panel says so, and says that the same tied matrix produces the logits. Similarity is described as a property of the learned weights, not of meaning.

The worker returns only the selected token's similarity row, not a full vocabulary-by-vocabulary matrix, so the cost grows linearly with vocabulary size. The same exporter writes `tests/fixtures/embedding.json`: rows, sums, and similarity rows at positions 0, 13, 14, and 15 of the recipe input. The engine matches it within the forward bounds. Its sum is bit-identical to the model's captured `embedding.output` in both the baseline and modified runs. A production test checks the displayed similarity ranking and values, and all 64 dimensions of each vector, at two positions.

## Ablation explorer

**Ablate each head for this prediction** (collapsed by default) runs one worker command. It sets each head's output to 0 at every position, one head at a time, from the current baseline, and reports the change in log p(target), the target's probability after, the distribution change (JSD), and the top prediction after. Each entry goes through the same comparison path as an on-screen edit (the cached suffix) and returns its full logits. Modified runs are released before the result is returned. Rows are ordered by effect. **Show** applies a row as the main experiment.

To make non-additivity visible, you can select two heads and ablate them together. The panel then reports the joint change beside the sum of the two single effects. The panel states that the measurements apply to this input, prediction position, and target only, and that ablation does not reveal what a head represents. For held-out-wide context, see the head-ablation coverage in `docs/retrieval.md`.

Verification: `scripts/export_ablation.py` (`npm run fixtures:ablation`) exports, for three trained-model inputs, the baseline logits, all eight single-head ablations, and three pairs (across layers and within each layer). The engine matches every logit within the forward bounds, with a maximum error of 4.29e-6. Each entry's metrics are identical to the comparison code applied to its returned logits. Single ablations use the cached suffix; cross-layer pairs use full execution. Tensor counts return to their starting value. A production test compares every displayed Δ log p and probability with values derived from the PyTorch logits, within the four-decimal rounding plus twice the logit bound. It also checks a pair result, **Show**, and page-width containment.

The fixture shows how strong non-additivity can be. On `A = 2 ; C = 0 ; B = 3 ; ? A =`, ablating Layer 1 Head 2 or Layer 1 Head 4 alone changes log p(`2`) by less than 0.001 nats in total, while ablating both changes it by −5.03. On the Task 1 input, Layer 1 Head 4 and Layer 2 Head 2 together give −6.74, against a sum of −12.13. These are measurements on single inputs; they suggest redundant or interacting routes but do not identify them.
