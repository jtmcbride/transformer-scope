# Text checkpoint probes, version 2 (draft)

Status: draft, awaiting approval (2026-10-13). Nothing in it has been run against a trained checkpoint. It revises only the name-copying probe of `docs/text-checkpoint-proposal.md` (version 1); every other criterion there is unchanged.

## Why a second version

Version 1 allowed one training run and one retry. Both failed the name-copying gate (80% top-1 over 200 prompts): 77.5% at 24,000 steps and 56.0% at 48,000 steps. Both results stay recorded in version 1, and version 1's gate stays failed.

The failures point at the probe rather than the model:

- When the model chose among the listed names, it chose the right one in 97% (24k) and 91.5% (48k) of prompts. A name that never appeared got a mean probability of about 0.003 and 0.002.
- Every wrong top-1 prediction was a pronoun (" her", " she", " his", " he"). The templates ended where a pronoun is a natural next word, for example `"Look!" said` → " her mom".
- The 48k run fit the data better (validation loss 1.838 → 1.772) and scored lower on the probe. A test whose score falls as the model better learns the text is measuring the wrong thing.

The probe's top-1 criterion asks two questions at once: will the next word be a name, and if so, which name. Only the second one is name copying.

## Disclosures

- This version was written after both version 1 results were known, and its templates were designed to remove the competing continuations seen there. That makes a pass more likely by design. It is a fix to a mis-specified probe; the 80% threshold and the 200-prompt size are unchanged.
- The version 1 diagnostic "right name outranks the other names" was 97% and 91.5%. Because that result is known, it is reported here but does not gate.
- The cue phrases were chosen using counts from the training text (below). No version 2 template, name list, or scoring rule has been run against either trained checkpoint.

## Probes

All prompts use one name in context; the expected continuation is that name with a leading space. Prompts are generated by seed 2028: 25 per gate template, alternating boy and girl, with places and objects drawn from version 1's lists. The same 200 draws are used with familiar and with invented names, so the two conditions differ only in the name.

### G1. Name copying, familiar names (gate)

- **Names:** version 1's lists (11 girls' and 10 boys' names, each one token, matched to the template's boy or girl).
- **Pass:** the name is the top-1 next token in at least 80% of 200 prompts.

### G2. Name copying, invented names (gate)

- **Names:** 20 invented names, none of which occurs as a capitalized word in the 250,000 training stories or the validation stories (checked 2026-10-13). Each is 3 or 4 tokens, so it cannot be predicted from a single learned token and has to be copied piece by piece. The proposal's original "held-out names" requirement was not met by version 1, which used common names.

  `Zorbin, Mirelda, Pellam, Drisko, Fennick, Tibbet, Selvy, Wendrick, Morrent, Gorrin, Haskel, Jorvel, Kalvin, Lumora, Ospen, Prellin, Tavrin, Wenlo, Zennick, Hollin`

- **Pass:** greedy decoding from the slot reproduces every token of the name, in order, in at least 80% of 200 prompts. The first-token top-1 rate is also reported.

### G3. Pronoun agreement (gate, unchanged)

Version 1's template, seed, and 80% threshold. It passed 200/200 on both checkpoints.

### Reported without a threshold

- **Selection among names:** the expected name has a higher sequence probability than every other name in its list (teacher-forced over all of the name's tokens).
- **Control:** for each prompt, the same prompt with a different name from the same list in context. Reported as the mean and median log-probability gain of the expected name, in context against out of context. This is version 1's "near the base rate" control made specific: the out-of-context probability is the base rate.
- **Random-token induction (mechanism check):** 100 sequences of 24 tokens drawn uniformly from the merged tokens (IDs 259–2047), each repeated once after `<BOS>` (49 tokens). Reports top-1 accuracy on tokens 2–24 of the second copy, against the same positions in the first copy. Random tokens are far from TinyStories, so this is a check on the copying mechanism, not a gate.
- **Per-template results** for every gate probe, and the most frequent wrong top-1 tokens.

## Templates

`{He}`, `{he}`, and `{his}` follow the template's boy or girl. The prompt ends at the slot; the name follows.

### Gate templates (frozen on approval)

1. `Once upon a time, there was a little {kind} named {name}. {He} lived near the {place}. One day, a bird asked the {kind}, "What is your name?" The {kind} said, "My name is`
2. `There was a {kind} named {name} who loved the {place}. Every day, {he} played with a {object}. All the kids in the town knew the {kind}. The {kind}'s name was`
3. `Once upon a time, a little {kind} named {name} found a {object} at the {place}. {He} was very happy. Mom smiled and wrote a note for the little {kind} named`
4. `In a small house lived a {kind} named {name}. {He} had a big {object}. One morning, Mom wrote a name on the {object}. The name she wrote was`
5. `There was a {kind} named {name}. Today was {his} birthday. Mom made a big cake. All the friends came to the party for the {kind} named`
6. `Once upon a time, there was a {kind} named {name}. {He} made a sign for {his} room and put {his} name on it. The name on the sign was`
7. `One day, a {kind} named {name} went to the {place} with a {object}. A new friend came and said, "Hi, I am new here. What is your name?" The {kind} said, "Hi, my name is`
8. `A {kind} named {name} lived in a small town. {He} was kind to everyone and always shared {his} {object}. Everyone in the town knew about the {kind} named`

Over every name, place, object, and boy or girl, the longest prompt plus its name is 55 tokens, within the 64-token context.

How often each cue is followed by a capitalized word in the training stories (excluding "I", "A", and "The"). This counts names and words like "Mom" together, so it is an upper bound on name continuations:

| Cue | Templates | Occurrences | Capitalized |
| --- | --- | --- | --- |
| `My name is` / `my name is` | 1, 7 | 1,338 / 193 | 100% / 99% |
| `'s name was`, ` name was` | 2, 4, 6 | 375, 2,401 | 99%, 98% |
| ` named` | 3, 5, 8 | 190,029 | 100% |

Cues considered and dropped for being weak: `Happy birthday,` (81%), `Thank you,` (67%), `Good night,` (55%), `the room of` (2 occurrences).

### Practice templates

Version 1's three `nameRepeat` templates. They may be run on any checkpoint while the probe code is developed. Gate templates are run only against a smoke-test checkpoint (a 60-step run in a scratch directory) until the gate run.

## Procedure

1. Approve this document, including the decisions below.
2. Implement the version 2 probes in `scripts/text_probes.py`, keeping the version 1 probes and their outputs unchanged. The gate templates, name lists, seeds, and thresholds become one frozen specification. `probes.json` records its SHA-256, and a test checks it against the value written here on approval.
3. Commit and push the frozen specification, and confirm CI passes, before any gate run.
4. Run the probes once on the 48,000-step export and once on the 24,000-step export, and record all results here whatever they are.

## Acceptance

- **Candidate:** the 48,000-step checkpoint (weights SHA-256 `0011a5f8e314f63325a7231dfa60664e5bab37dbd8a27c1e5c03fab45996f294`), the later of the two and the one version 1's retry produced. The 24,000-step checkpoint is scored and reported but cannot be accepted, so the choice between them is not made after seeing results.
- **Gate:** G1, G2, and G3 all pass, and version 1's criterion 2 (already met) still holds. Version 1's determinism requirement still applies before anything ships: a second identical 48,000-step run on the training host must reproduce the weight hash.
- **If the gate fails:** the text checkpoint is closed. There is no version 3 of these probes. A further attempt would need a new proposal with a different model, data, or training budget, trained and evaluated under probes fixed in advance.
- **If it passes:** continue with version 1's work order, steps 5–7: fixtures and parity, free-text input, and prepared recipes. The audit-set loss is still reported once, at the end.
