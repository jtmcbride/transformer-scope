# Controlled text continuation

The TinyStories workspace offers **Watch a story grow token by token** below the flow diagram, linked from the prompt editor. Step one token computes a single step and pauses; Play story continues at a readable pace, with 300 ms between completed steps. Stop generation immediately terminates the continuation worker and keeps the last completed step. Step/Play resume that exact prefix. Reset story returns to the completed prompt and captures fresh settings on the next step. Prompt drafts do not change a continuation. Running a new prompt or Reset story begins a new workspace. Browser reload and diagram-worker restart reopen the saved workspace for this checkpoint; switching away retains its saved copy. Download before starting a new prompt to keep the earlier experiment.

The original prompt is muted in the reading view, generated text is darker, and numbered chips retain each generated token. Tooltips and the latest-token line show the raw model softmax probability, before temperature/top-p filtering. This is a short continuation from an experimental checkpoint, not a promise of a complete or coherent story. The earlier name-copying gate remains failed.

## Sampling contract

- Most likely token uses temperature zero, ranking eligible logits with lower token ID as the tie breaker.
- Seeded sampling uses temperature in (0, 2], top-p in (0, 1], and an unsigned 32-bit seed. Settings freeze at the first step. Reset to change them.
- BOS (0) and PAD (2) are excluded from generation. EOS (1) remains eligible and ends its branch. Probabilities reported on screen remain from the unfiltered full-vocabulary model softmax.
- Temperature rescales logits after subtracting the eligible maximum. Top-p sorts by probability with ID tie breaking, retains the smallest prefix whose cumulative probability reaches the threshold, includes the boundary token, and renormalizes that prefix before drawing.
- `drawAt(seed, step)` provides a counter-based uniform draw. Both branches receive the same draw at a given step. Their prompts can diverge, so this is controlled branching, not an assertion that later probability differences have the same input. Repeating settings on the same CPU runtime is reproducible; floating-point differences can change near-tied choices on other environments.
- Exact token IDs are appended to each prefix. Displayed text is never re-tokenized, so BPE merges, spaces, punctuation, and partial UTF-8 pieces cannot change computation boundaries. Preview holds an incomplete trailing character until further bytes arrive; invalid completed byte sequences display as replacement characters. Raw byte-piece labels remain in the token strip and download, including when a limit ends mid-character. Strict decoding of ordinary input remains strict and preserves a leading UTF-8 BOM.

Each branch stops independently at EOS, the new-token budget (1–64), or 64 total tokens including BOS. A full prompt cannot append a token. No rolling window, position rebasing, silent truncation, or KV cache is used. The default budget is 24 new tokens, further bounded by available context. The final appended token is included in that total-token limit.

## Original and edited stories

First make a head-output edit in the diagram, applied at all positions. Enable **Compare with current head edit** before starting. The panel snapshots that one head's layer, head, factor, and all-position scope. It applies the edit at every position of each growing edited prefix. The original branch uses unmodified weights. Later diagram edits do not change a started continuation; its captured edit stays labeled until Reset. Attention redirects, residual copying, and position-specific head edits remain available in the diagram but are not continuation controls in this slice.

A paired step commits only after both active branches finish. A cancellation or error cannot publish half a pair. Each branch then feeds its own chosen token into its own next step. A branch that has ended remains fixed while the other continues.

## Runtime and records

Generation loads the exact shipped checkpoint lazily into one separate CPU module worker, independently of the diagram's selected backend and cached runs. This avoids compiling a new WebGL shape for every prefix length and makes cancellation immediate without ending the inspection workspace. All temporary baseline and modified run descriptors/tensors are released after each prediction. Stop, Reset, model/prompt changes, and unmount terminate the continuation worker. There is at most one generation step in flight; it does not prefetch future tokens. The ordinary worker's numerical tolerances are unchanged.

Download continuation writes `transformer-microscope-continuation`, schema version 1: checkpoint identity/hashes, CPU backend, exact prompt text and IDs, captured sampling settings/edit, step count, both token prefixes, selected IDs/raw model probabilities, and per-branch stop reason. This is a generation record, separate from the replayable diagram experiment format. Continuation import, rolling contexts, and generation performance claims on physical mobile are deferred.

`scripts/export_continuation.py` independently rolls out the shipped weights in PyTorch for 16 original and 16 edited greedy steps from the red-ball prompt. The checked-in fixture fixes each chosen ID, probability, and complete prefix. Engine and production browser tests compare every generated token to it. The edited branch diverges after five matching tokens: the original continues “He ran to his friend” while the edited branch continues “He asked his friend.” This is one measured example, not a general role assigned to the head.

Additional engine checks cover BOS/PAD masking, eligible EOS, stable ties, temperature shift invariance, top-p boundary inclusion, seeded draws, atomic failures, independently ended branches, exact noncanonical BPE prefixes, incomplete UTF-8 and BOM preservation, context/token limits, and zero retained tensors after a complete paired rollout. Browser checks cover stepping, frozen edits despite diagram changes, view switching, seeded replay across step/play, draft separation, full-context refusal, mobile containment, cancellation during delayed inference, and model switching without late results. Hosted verification exercises paired generation against the same independent fixture after deployment.

## Inspect a generated token

Select any numbered generated-token button (mouse, touch, or keyboard) to pause playback and open **How the model chose …** below the story. Previous/Next token navigate completed tokens in that same branch. Close returns focus to the selected token. Inspection does not change the prompt editor, the main experiment, generation settings, or the recorded story. Step/Play can continue the story while an already selected historical step stays fixed. Reset, a new completed prompt, model switching, and worker restart close the inspection.

The inspected input is exactly `branch.tokenIds.slice(0, promptLength + zeroBasedChoiceIndex)`. It excludes the selected output token and every later token, includes BOS, and preserves raw BPE IDs even for incomplete UTF-8 or noncanonical boundaries. The prediction comes from the last input position. An EOS token can be inspected just like any other completed choice. Display text is only a preview, never an inference input.

For the original branch there is no intervention. For the edited branch the frozen all-position head edit is applied to that branch's own prefix. The reference and edited runs inside this historical diagram use the **same edited prefix**; the reference is explicitly labeled “Without edit · same context,” not presented as the separately generated original story after divergence. Attention comes from the selected branch, including downstream changes from an earlier-layer edit. The historical diagram is read-only. Separate branching controls below it create a new comparison without changing the recorded step.

The inspector reuses the visual transformer flow and stage inspector. Select embedding, any layer/head, residual addition, MLP output, or readout to see measured values at the final input position; **Inspect full vector** opens each dimension. The selected token's raw model probability is always displayed separately from the most-likely prediction, including when sampling selected a lower-ranked token. The diagram probabilities precede temperature, top-p, and BOS/PAD masking.

A separate lazy CPU worker loads the same revision and weight/tokenizer hashes, reconstructs the input and edit, and repeats the recorded greedy or seeded draw. It must reproduce the selected ID and raw probability (absolute probability difference at most 1e-6) before exposing the flow. This replay check supplements, and does not alter, existing tensor parity tolerances. A mismatch or unavailable checkpoint is an error, not a fallback to new weights. Switching tokens or closing inspection terminates that worker and all its run descriptors, cached tensors, and outstanding reads. At most one historical worker is retained; selecting a token also stops the generation worker. Later explicit playback may use its own generation worker alongside the fixed inspection.

Verification covers exact pre-token prefixes in both diverged branches, independent PyTorch probabilities, muted-head output vectors, layer navigation, full vectors, seeded-choice replay, partial-byte/EOS selection, keyboard controls, small-screen containment, unchanged generation records, and delayed worker responses during switching/closing/reset/model changes. The deployed continuation check also opens edited step seven and verifies its context, probability, and muted-head output.


## Change a head and branch from a generated token

After selecting a generated token, choose a head in its historical flow and use **Continue two stories from step …**. Mute, Normal, Amplify, or an exact strength from 0 to 2 set a draft change. **Compare from this token** captures that change and plays two new continuations from the exact prefix before the selected output. The selected token is regenerated. The original story and main experiment remain intact.

**Keep source settings** reuses the selected branch's captured intervention, if any. **With head change** replaces that intervention when it targets the same head, or retains it and adds the new edit when it targets another head. This avoids multiplying overlapping scale edits. Both paths start with the same exact prefix and use the recorded temperature, top-p, seed, and original step counter. They then follow their own generated tokens. The reference therefore reproduces the recorded source tail while that tail exists; it can continue beyond the source's former new-token budget, within the same 64-token context.

The scope is explicit: the head output is scaled at **all input positions** during the affected forward pass. **From this token onward** keeps the edit for every prediction in this comparison. **Only this prediction** applies it for the first regenerated token, then restores the source intervention settings for subsequent predictions. The resulting text can still diverge because the changed token feeds future predictions. This is a temporal edit policy, not a claim that only one position's internal activations change.

Both branches retain BOS/PAD masking, independent EOS/context/budget stops, atomic paired steps, and shared sampling draws. A fork begins with `drawOffset = source.step - 1`; pausing/resuming never restarts the random sequence. The new-token limit counts regenerated tokens, including the selected token. A selected EOS can also be regenerated because its prefix excludes EOS.

The comparison marks the first differing token step and highlights differences at matching generation steps. This is token-step alignment, not word alignment or a quality score. An unchanged sequence is explicitly reported; a head edit need not change the chosen tokens. The historical flow remains a view of the recorded computation, while the branch form is labeled as a draft and finished results retain their captured edit label.

A lazy CPU worker owns the fork computation; the common story runtime checks the checkpoint revision and weight/tokenizer hashes and releases temporary runs after each prediction. Starting a comparison pauses parent-story playback. Stop terminates the fork worker and retains the last completed pair; Step/Play resume it. Clear, choosing another source token, closing inspection, model/prompt replacement, and unmount terminate pending work. Completed snapshots stay in the workspace until Reset story or running a new prompt. Each selected-token inspector retains its own comparison. Selecting a completed token in either fork pauses that fork and opens a deeper inspector. Its parent comparison stays in memory, with the parent inspector worker released until return. **Back to previous comparison** closes the current inspector, restores the parent results and keyboard focus, and reloads only the parent computation. All recorded comparisons remain in the branch map. Whole-workspace export/import is available; individual fork records remain standalone downloads. Selecting the same source token again keeps its open comparison.

**Download branch comparison** records `transformer-microscope-story-fork`, schema 2: checkpoint identity/hashes, CPU, immutable source selection (exact prefix, original selected choice/settings, all effective edits and subsequent edit settings), comparison depth, proposed head edit, duration, fork budget, draw offset, both completed branches, stop reasons, and first differing story step. Download before changing the inspected source token to preserve a comparison.

`scripts/export_story_forks.py` computes four independent 12-token PyTorch branch pairs from the shipped weights: sustained and one-prediction edits at original step six, an added different-head edit at edited step seven, and replacement of the captured same-head edit at edited step seven. Engine checks compare all IDs/probabilities and verify zero retained tensors, random-counter continuity, edit composition, atomic failure, EOS, raw byte prefixes, and context limits. Browser checks cover these four pairs, immutable source records, frozen result labels, seeded identity forks, stop/resume, late-result disposal, and narrow layout. Hosted verification repeats the same-head replacement case against the deployed worker. The model's quality gates and physical-device performance limitations are unchanged.


## Inspect and branch again

Every numbered token in **Keep source settings** and **With head change** opens the flow for that path's exact pre-token prefix. The heading names the comparison depth, path, and original story step. Previous/Next stay within that path's completed tokens. Inspection repeats the recorded sampling draw and checks both the chosen ID and raw probability before showing results, just as for the initial story. All captured heads appear in the edit description; the baseline is unedited computation on this same prefix.

Further comparisons preserve the selected token's global sampling counter and all inherited head edits. The source selection stores `edits` for the selected prediction and `continuationEdits` for later predictions. This distinction preserves one-prediction expiry even when branching from the very token affected by that temporary edit. A new sustained edit replaces the selected head on every future prediction, while the source's other temporary edits still expire. A new one-prediction edit expires along with the applicable source policy. Changing the same head replaces its strength; changing another head adds to the captured set. Exact token IDs are never decoded and re-tokenized.

Ancestor results remain unchanged while descending. Only the active inspector retains a model worker; selecting a branch token terminates its generation worker and suspends the parent inspector. Closing or navigating inspectors preserves comparison records in the workspace map. Root-story reset and running a new prompt clear the workspace; download the whole experiment first to keep it. The 64-token context still applies at every depth.

`scripts/export_nested_story_forks.py` supplies three independent PyTorch cases for a second and third head change and inherited one-prediction expiry. Engine checks cover exact prefixes, multi-head replay, future edit policies, seeded counter continuity, and tensor cleanup. Browser checks cover both paths, deeper comparisons, keyboard return, unchanged ancestors, mobile layout, bounded live workers, and delayed cancellation. Hosted verification inspects a branch result and creates another comparison from it.


## Persistent story workspace

The branch map keeps a source story and comparison records independently of their open inspectors. Every new comparison gets a separate ID, parent link, frozen plan, and latest completed paired frame. Starting another comparison at the same token retains earlier results. Map entries show their source path, story step, head strength, and whether the edit applies once or onward. Selecting an entry reopens its original token inspection and results; only the active inspector and active generation own computation workers.

The workspace automatically saves completed frames to local browser storage after each step. Reload restores the exact source prompt, tokens, sampling settings, comparison tree, and selected map path, with playback paused. Paused source stories and comparisons resume from their saved frame and original random counter. Browser storage is per checkpoint model ID; revision and weight/tokenizer hashes must match before reopening. Failed storage writes are visible and leave the in-memory experiment downloadable. Storage is local to this browser, and the UI does not claim success after a failed write.

**Download workspace** exports `transformer-story-workspace`, version 2 (with version 1 import migration), containing checkpoint identity, root story, all comparison IDs/parent links/plans/frames, and selected path. **Open workspace** validates the entire file before replacing the active experiment. Validation checks exact parent-derived source selections, edit policies, vocabulary, prefixes, choice probabilities, stop reasons, paired step counts, unique IDs, parent order, and selected path. Files are bounded to 10 MB and 500 comparisons. Inspectors replay the selected computation before displaying values; import validation does not assert numerical verification of every historical token. Invalid imports preserve the existing workspace.

Reset story and Run input start a fresh workspace; Reset retains the sampling controls. Downloads remain the way to keep multiple experiments or move between browsers. Individual continuation and fork download formats remain unchanged. A complete saved tree is a workspace file, not an experiment recipe for the main diagram. Cross-tab synchronization and cloud storage are outside this slice.


## Explain a head change at the branch point

Each captured comparison shows **How this head change shifts the prediction**. Two forwards use the exact same pre-token prefix: the reference keeps the source's effective edits, and the changed prediction replaces/adds the new head edit. This isolates the new change relative to inherited settings, including one-prediction policies. It does not decompose interacting heads into independent contributions.

The selected source token is always shown with raw before/after probabilities, signed percentage-point change, and ranks. Alternatives are the union of the top five model predictions on either side, plus the actual choices under the recorded greedy or seeded sampler. BOS/PAD are excluded from ranks and candidates but remain in the full-vocabulary raw softmax; EOS remains eligible. Stable ties use lower token ID. Probability bars use one absolute 0–100% scale, and numbers round to four decimal places. These are probabilities before temperature/top-p/filtering; the explanation explicitly names the resulting sampled choices, which need not be the top-ranked raw prediction.

Only the first prediction uses the shared starting context. If it stays unchanged, the report says so. Later differences can arise from continued head edits and eventually different text inputs, so the initial probability change is not a token-by-token attribution for the rest of the story. This display describes measured changes in prediction, not a general semantic role for a head.

The active historical inspection worker computes the two predictions and releases its temporary runs. No additional model worker is loaded. Reports are derived from the frozen plan, not draft controls, and recompute when a saved comparison is reopened. No workspace-file migration is needed; existing records already preserve the exact source and policy. Closing/navigation ignores stale responses, while normal shared-worker cleanup releases their tensors.


## Scan all heads at a selected token

**Scan all heads** tests Mute (0×), Normal (1×), and Amplify (2×) at every layer/head: 48 independent trials for this model's 16 heads. Every trial uses the exact same pre-token prefix, source edits, and sampling counter. Changing the same head replaces its captured strength; other captured heads stay in place. Normal can therefore restore an inherited edit rather than being a universal no-op. Each edit scales head output at all input positions for this prediction.

Results show the selected token's raw probability, signed percentage-point change, rank, and whether the recorded sampler would choose a different next token. Sort by absolute change, increase, or decrease; eight results are shown initially, with an option to show all. Rankings use unrounded probability differences, then layer, head, and factor as deterministic tie-breakers. Tiny differences can round to zero. These are prompt-specific individual effects, not a decomposition into additive head contributions.

The scan runs sequentially in a temporary CPU worker with the same hash-checked checkpoint. Progress counts completed trials. Stop terminates that worker immediately and keeps only completed results, clearly marked partial. Navigation/unmount terminates the worker and ignores late responses. A scan never silently starts story generation. Generation controls are blocked while scanning; starting a scan pauses parent generation.

**Use this change** selects that head in the flow, fills the branch strength, focuses the branch controls, and shows the existing before/after probability preview. Choose the duration and token budget, then **Compare from this token** captures the proposed edit and generates both paths using the normal workspace machinery. Saved comparisons retain the chosen edit and source; scan rankings are derived exploration results and are recomputed rather than saved in workspace files. Partial results cannot establish the strongest effect among unmeasured heads.

## Two-head comparisons from the scan

Select **Select for pair** on two different heads, then **Compare selected heads**. Changing the strength of a selected head replaces that selection; a third head is disabled until one is removed. The selection summary retains both heads when sorting or collapsing the scan results. **Use this change** retains the existing single-head workflow.

The draft measures four exact-prefix predictions: captured source settings, the first change alone, the second alone, and both together. Every trial preserves unrelated inherited edits and replaces the proposed head's captured strength. The combined distribution is computed afresh, including its selected-token probability/rank, strongest alternatives, and original global sampling draw. It is never estimated by adding individual effects. The report also shows the sum of individual percentage-point changes and `combined delta − sum`, an interaction measure specific to this prefix and token. A positive interaction is more favorable to the selected token than the sum; it does not establish a general head role or mean the probability increased.

The pair shares the duration and token budget selected in the draft. Both changes apply from the branch point onward or only to its first prediction; after expiry, each subsequent prediction uses the source's captured future settings. Both continuations retain exact IDs, deterministic shared draws, atomic pair publication, independent stopping, and the 64-token context limit. Inspecting either path reconstructs all effective edits, and another fork can replace a head or add another change. Switching back to a one-head draft does not alter a captured comparison.

`ForkPlan.edit` remains the primary change; optional `additionalEdits` contains at most one additional all-position head scale. Duplicate heads, malformed arrays, out-of-range strengths, and more than two proposed heads are rejected. Inherited edits may contain more heads. Pair comparison downloads use schema **3**; single-head downloads remain schema **2**. Workspace exports now use version **2**, which requires preserving this proposed pair. Version **1** workspaces without pair proposals migrate on import/reopening; a pair labeled as version 1 is rejected. The unchanged checkpoint validation and full parent/source checks still apply. Scan rows and uncommitted pair selections remain temporary.

Independent references are generated with `.venv/bin/python scripts/export_story_head_pairs.py` from the shipped weights, using the separate PyTorch forward implementation. Four six-token cases cover sustained and one-prediction pairs, replacing an inherited edit while retaining another, and an inherited edit expiring while the new pair continues. Fixtures include raw individual/joint probabilities, candidate ranks/choices, alternatives, interaction, and both complete token paths. Engine checks also cover failed-step atomicity, seeded shared draws, cancellation, snapshot cloning, invalid proposals, version migration, and tensor cleanup. Browser checks exercise keyboard selection, strength replacement, the two-head limit, mobile containment, both durations, nested inspection/forking, reload, and workspace export/import. Hosted release checks exercise a two-head identity pair, its exported record, saved workspace, and computation replay.

## Scan pairs of heads

**Scan head pairs** measures every distinct pair of heads at the selected generated token and ranks either their interaction or the actual joint change in its raw probability. The default **Mute both** scope contains 120 pairs for the 16-head TinyStories model. **Amplify both** and **Normal both** also contain 120 trials each. Mixed **Mute + Amplify**, **Mute + Normal**, and **Normal + Amplify** scopes contain 240 trials: both assignments are tested for every pair. **All strengths** measures all nine 0×/1×/2× assignments on every pair, totaling 1,080 trials. No pairs are shortlisted using single-head scores, so a pair with small individual effects can still rank highly. Scope counts are visible before starting; all-strength scans take longer.

Every trial uses the exact pre-token IDs, captured source settings, and global sampling draw. It replaces the two targeted strengths and retains unrelated inherited head edits. The baseline is checked against the recorded prediction before publishing results. One unedited prefix baseline is retained in the scan worker for the scan's lifetime; the source, every joint trial, and each individual head/strength are evaluated separately against it, with modified runs released after each trial. The retained baseline is released on completion/error, and terminating the worker releases pending scan work on stop/navigation. Reusing a baseline across different prefixes is rejected.

The default **Strongest interaction (absolute)** ranking uses `I = (pAB − p0) − [(pA − p0) + (pB − p0)]`. All four probabilities describe the same selected token and exact source prefix. Each individual trial changes only its own head while retaining all other source settings, including an inherited edit on the other head. A single-head trial is reused by its head/strength key only within this scan: at most 16 additional trials for a same-strength scope, 32 for a mixed scope, and 48 for all strengths. A row is published only after its joint and both individual measurements finish; cancellation or failure cannot publish an incomplete interaction.

**Most positive interaction** and **Most negative interaction** offer signed rankings. Positive means a greater increase or smaller decrease than the sum; negative means a smaller increase or greater decrease. The sign does not describe the net probability change, and a pair can have a large interaction with a small net effect. This is non-additivity on the raw probability scale, including nonlinear probability read-out; it is specific to this token and text, not evidence of a general head role. For example, individual changes of −10 and −5 percentage points with a joint change of −4 give interaction +11 percentage points.

The existing largest absolute change, increase, and decrease rankings remain available. Each row shows both strengths, the individual changes and their sum, the joint probability and change, signed interaction, token rank, and whether the recorded sampler would select another token. Eight results are visible initially; the complete list is available once the scan stops. Rankings use the chosen unrounded metric, then canonical layer/head pairs and strengths for deterministic ties. A completed ranking is exhaustive only within the chosen strength scope. Stopped/error results are explicitly partial and cannot establish a strongest unmeasured pair. Changing scope clears previous scan rows, so results cannot be relabeled with different strengths.

**Use this pair** fills the existing two-head draft and recomputes its individual and joint probability preview. Choose duration and token budget, then **Compare from this token** creates a normal persistent comparison. Both heads remain available in saved plans, token computation inspection, and further forks. Scan rankings remain temporary; the selected pair is captured in the workspace when a comparison starts. Single-head and pair scans exclude one another, and both block story generation while running. Source-token changes, deeper inspection, and returning from a comparison discard pending scan results and restore usable controls.

Each scan also exports six-token continuations for its strongest absolute-effect and absolute-interaction pairs. Engine checks verify every probability, rank and choice, all 1,080 strength/head enumerations, both mixed assignments, inherited edit replacement, source immutability, stable ranking, shared seeded draws, cancellation, replay failure, baseline reuse, descriptor release, and tensor cleanup. Browser checks verify a complete default scan against every reference row, all six sorting modes, branching with its strongest-interaction pair, narrow-screen containment, saved-result reopening, usable partial mixed-scope results, mutual exclusion, and late-result disposal.
