# Computation workspace, first milestone

The main screen follows three steps: set an input, inspect the computation, and compare the prediction. The retrieval editor presents key–value bindings and a query, with **Edit tokens** for arbitrary symbol inputs. Editing either form creates a draft; **Run input** creates the baseline. Export always records the completed input, even while a draft is present.

The computation graph is built from the loaded checkpoint's layer and head counts. Each layer shows normalization, parallel attention heads, their shared projection, two residual addition junctions and bypasses, and the MLP. Layers can be collapsed. The final readout describes normalization, tied unembedding, and softmax.

Selecting a node is inspection, not an intervention. It reads baseline and modified vectors from the completed runs at the labeled position. The selected node has a green outline; the completed intervention has an amber **Edited here** marker. Neither style claims that a node has a measured effect on the prediction. Inspector norms and component changes describe only the selected vector.

Head selection opens contextual strength controls. **Mute**, **Normal**, and **Amplify** submit factors 0, 1, and 2 through the existing comparison queue; the slider, exact value, and position scope remain available. Selecting another head leaves the active experiment intact until a control is edited. That head starts at normal strength. Attention redirects and residual patches retain their existing controls and engine paths.

The result card shows the baseline and modified top tokens and the selected target's probabilities. It is sticky beside the workspace on desktop and fixed at the bottom on screens up to 800 px wide. Mobile node selection brings the inspector into view. Pending computations explicitly label the card as the last completed result. The graph's intervention marker also follows the completed result, while controls describe the requested edit. Export is disabled until it completes. A lost worker labels the result as belonging to an ended session.

Detailed attention matrices, vectors, residual readouts, ablations, replay reports, reference verification, and save/replay remain available below the workspace. The first milestone does not change the model contract, worker commands, experiment schema, or numerical execution strategy.

Implementation: `InputEditor`, `ComputationGraph`, `NodeInspector`, and `PredictionSummary` in `src/components`, integrated in `App.tsx`. `flow.css` defines the responsive workspace while existing detailed inspectors retain their styles.

Production browser coverage in `tests/browser/flowchart.spec.ts` checks immutable navigation, keyboard activation, selected-head ablation logits against the independent PyTorch fixture, structured drafts and exports, stage-vector norms, narrow-screen result visibility, reset, and pending-result labeling. Existing browser tests continue to cover replay, recovery, redirects, patches, detailed numerical inspection, and the opt-in study and validation pages.

**Milestone 2 — effect tracing**

**Follow the change** opens an opt-in trace for the completed head-scaling experiment. **Previous** and **Next** walk through the edited head, shared projection, residual additions, MLP, later parallel heads, and final prediction. The navigation bar remains visible, along with the prediction summary on mobile. Layers expand as the guided step advances. Clicking a graph node synchronizes the guide or enters manual inspection. Selecting **Trace inspection position** changes the inspected rows without changing the intervention or prediction position.

Route annotations and measurement badges have independent meanings. **Can affect this prediction** is determined by the transformer architecture, including earlier-to-later position flow through attention. **Local downstream computation** identifies an edited computation that cannot reach the selected prediction. A single-position edit gains an explicit handoff at the next attention layer when it can reach a later prediction. **Exact match**, **Small difference**, and **Changed** describe the measured vectors at the labeled inspection position. Nonzero differences use scientific notation when needed; the small-difference category uses the verified numerical bounds as a display convention, not an importance or causality score.

Heads display their attention-row and output differences separately. Same-layer head-output scaling leaves the head's attention row and raw output unchanged. Earlier-layer edits can change a later head's inputs and attention. Residual nodes display diagnostic readouts at the prediction position, which can differ from the inspected vector's position. Only the final readout is labeled **Model prediction** and uses the saved completed comparison. The guide identifies the first diagnostic stage where the modified preferred token differs from the baseline's. Intermediate readouts are inspections, not semantic roles assigned to a layer.

The small-effect recipe illustrates why these labels are separate: its final logit vector has a maximum change of about 0.00226 in the PyTorch fixture, while its target-probability change is tiny. The inspector displays a nonzero Δ log p in scientific notation even when the displayed percentages agree. The no-path recipe displays local changes at position 0 and an exact prediction match at position 15. Normal strength is labeled as a selection with no effective edit.

`useEffectTrace` measures only while tracing is open. It coalesces completed edits, allows one trace request in flight, and discards responses whose run/session key has changed. Navigation and position selection reuse the measured report. Export preserves navigation; input replacement, replay, new interventions, and worker restart reset it. During pending work, measurements are cleared and the toolbar says it is waiting. Context loss clears trace annotations and labels the ended session; CPU recovery creates a new trace. Attention redirect and residual patch modes retain their first-milestone interfaces; trace guidance is currently available for head scaling.

Verification: 68 engine tests and 38 Chromium production tests passed, including all seven independent trace fixtures on worker CPU and WebGL, resource cleanup, rapid edits, checkpoint switching, replay, export, context loss during tracing, and viewport/keyboard checks at 360, 390, and 768 px. These are automated browser and layout checks, not physical-device evidence. Firefox and WebKit were not run for this milestone.

A separate isolated Chromium sample measured trace worker computation at 34.9 ms on CPU and 268.6 ms on WebGL. Automated time from opening the guide to readiness was 222.5 ms and 843.7 ms respectively, including browser automation and request coalescing. With tracing closed, an ordinary slider edit reached the completed result in 46.8 ms on CPU and 43.0 ms on WebGL. Guided navigation issued zero additional trace requests on either backend. These are single-session samples, not device percentile estimates or a controlled before/after benchmark.
