# Names, ancestry, and saved workspaces

The story header identifies the current workspace and its browser-save status. **Branch history** jumps to a compact nested map. Each comparison appears beneath its actual parent, with the generation step, source or changed path, exact head settings, duration, stable comparison number, and shared A/B membership. The current comparison and the path to it are highlighted. Deep histories keep bounded indentation and show depth explicitly.

Suggested labels describe the performed edit and actual selected token, such as **Muted L1/H1 at “ran”**. Select a comparison and choose **Rename comparison**, or use **Rename workspace**. Names accept up to 80 characters; blank restores the suggested label. Enter saves a name, and Cancel leaves it unchanged. Custom names appear in history, path selectors, shared results, and recorded-token context. Captured source labels remain available as provenance. Renaming changes no predictions, settings, ancestry, or completed measurements.

**Saved workspaces** lists earlier experiments with their names, saved time, comparison count, and Open/Download controls. Run input, Reset story, and importing a valid file preserve the previous workspace before activating another. Reset retains the current sampling controls; opening a saved workspace restores its own starting text, frames, ancestry, selected route, edits/expiry and sampling counters. Starting a different editor prompt does not replace the saved story's text. Empty drafts are reused rather than filling the history list. No real workspace is silently evicted. Removing an older workspace requires an explicit named confirmation; the active workspace cannot be removed.

Automatic saving uses one atomic library record per model, at `transformer-story-workspace:<modelId>:library`. Existing `transformer-story-workspace:<modelId>` data migrates without deleting that original record. A library envelope uses version 1; individual workspace files remain version 3 with validated optional `name` fields on the workspace and comparison nodes. Version 1/2 workspace files continue to migrate through the existing strict checkpoint, plan, frame, source and shared-link checks. Current-workspace downloads contain one complete workspace, not the library envelope.

Quota or unavailable storage leaves the current workspace visible and downloadable, reports that it is not saved, and blocks replacing it. After downloading or removing older work to free space, retry **Start new prompt workspace** if needed. A changed record from another tab is detected before writing: download local changes, then reload to reopen the newer library. Tabs do not merge concurrent edits. The library supports up to 1,000 records and reports that limit without evicting data. Browser storage can be cleared or evicted; downloads provide a separate backup.

Older-checkpoint workspaces remain listed for download and are not executed with the current model. Unreadable library data is preserved verbatim as a recovery download, together with an available legacy backup. Invalid imports leave current work untouched. Successful switching remounts the story and analysis owners, cancels old workers, and guards saves by active-workspace ID so obsolete replies cannot update another story. Presentation names are excluded from numerical analysis identities, keeping completed traces and prepared branch setups usable after a rename.
